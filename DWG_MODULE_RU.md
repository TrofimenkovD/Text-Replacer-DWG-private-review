# DWG-модуль TextReplacer

## Назначение

Модуль заменяет текст непосредственно средствами установленного AutoCAD,
без промежуточного преобразования всего чертежа `DWG → DXF → DWG`.

Состав:

- `dwg_autocad_adapter.py` — Python-оркестратор;
- `TextReplacer.BFind.lsp` — неинтерактивный AutoLISP-адаптер поиска;
- `LICENSE_NOTICE_RU.md` — условия передачи и публикации;
- `LEE_MAC_PERMISSION_REQUEST_EN.md` — заготовка запроса Lee Mac.

## Какие ошибки закрывает

- `ezdxf — invalid literal for int() with base 16`;
- отсутствие собранного `libdxfrw`;
- неполная/рискованная конвертация DWG через DXF;
- поиск кириллицы, сохранённой как литералы `\U+XXXX`;
- обход текста внутри определений блоков;
- обработка TEXT, MTEXT, ATTRIB, ATTDEF и обычных таблиц;
- неправильное изменение Excel-связанных таблиц.

## Поток обработки

```text
TextReplacer
    │
    ├─ резервная копия исходного DWG
    │
    └─ dwg_autocad_adapter.py
          │
          ├─ находит AutoCAD 2027…2020
          ├─ создаёт рабочую копию рядом с DWG
          ├─ запускает acad.exe или accoreconsole.exe
          ├─ загружает TextReplacer.BFind.lsp
          ├─ передаёт find/replace через environment
          ├─ получает OK:count:... из result.txt
          ├─ проверяет размер и заголовок AC10
          └─ атомарно заменяет рабочий DWG
```

Рабочая копия создаётся в каталоге исходного DWG. Это сохраняет разрешение
относительных XREF и позволяет использовать атомарный `os.replace` на том же
томе.

## Интеграция с публичным исходным кодом

1. Скопировать оба файла в корень приложения.
2. В `text_replacer.py` заменить текущий обработчик DWG:

```python
from dwg_autocad_adapter import replace_in_dwg
```

Сигнатура совместима с публичным API:

```python
result = replace_in_dwg(path, find, replace)
```

Если приложение использует собственный `ReplaceResult`, можно либо
преобразовать `DwgReplaceResult`, либо передать в проект поля `path`,
`kind`, `count`, `changes`, `error`.

3. При сборке PyInstaller добавить LISP как data-файл:

```python
datas=[
    ("TextReplacer.BFind.lsp", "."),
]
```

Для one-file сборки путь следует определять относительно `sys._MEIPASS`.
В переданном модуле обычный режим ожидает LISP рядом с Python-файлом.

## AutoCAD host

По умолчанию поиск выполняется в:

```
%ProgramFiles%\Autodesk\AutoCAD 2020…2027
%ProgramW6432%\Autodesk\AutoCAD 2020…2027
```

Новые версии перебираются первыми. Полный `acad.exe` имеет приоритет, потому
что даёт ActiveX-модель, необходимую для части таблиц. `accoreconsole.exe`
используется как запасной вариант.

Для диагностики конкретный host можно задать:

```powershell
$env:TEXTREPLACER_AUTOCAD_HOST =
  "C:\Program Files\Autodesk\AutoCAD 2025\accoreconsole.exe"
```

## Unicode

Для строки «ЦОД» Python передаёт две формы:

```
TEXTREPLACER_FIND=ЦОД
TEXTREPLACER_FIND_ESCAPED=\U+0426\U+041E\U+0414
```

Замена записывается обычной Unicode-кириллицей. Поэтому зашифрованная форма
после успешной замены нормализуется в читаемый текст.

## Excel Data Link

Ячейки таблицы, связанные с Excel, не следует менять внутри DWG. Они будут
перезаписаны при обновлении связи и могут отображаться наложенными. Адаптер
пропускает их, считает отдельно и возвращает инструкцию изменить исходный
Excel, затем обновить Data Link.

## Результат LISP

Файл результата содержит ASCII-строку:

```
OK:<replaced>:<scanned>:<text_objects>:<raw_hits>:<skipped>:<linked_skipped>:<escaped_length>
```

При ошибке:

```
ERROR:<description>
```

Python принимает изменение только при `OK:`, нулевом exit code, существующем
выходном файле, размере не менее 64 байт и заголовке `AC10`.

## Проверка

Фактически проверено на AutoCAD 2025:

- обычный текст в модели — заменён;
- видимое «ЦОД» в форме `\U+XXXX` — найдено;
- результат записан обычной кириллицей;
- текст в определениях блоков — обрабатывается;
- Excel-связанные ячейки — пропускаются с сообщением;
- невалидный результат не заменяет исходный DWG.

Каталоги AutoCAD 2020–2027 поддерживаются логикой обнаружения, но все восемь
версий не проходили полный регрессионный тест.

## Оптимизация

Для нескольких задач следует вызывать `replace_many_in_dwg()`, передавая
упорядоченный список пар. Тогда создаётся одна рабочая копия DWG, а окончательная
проверка и замена исходного файла выполняются один раз.

Сейчас AutoCAD запускается для каждой пары отдельно. Следующая оптимизация —
передавать весь список замен одному запуску AutoCAD и выполнять их в LISP за
один сеанс. Это существенно ускорит каталоги с большим числом задач, но порядок
замен должен сохраняться.
